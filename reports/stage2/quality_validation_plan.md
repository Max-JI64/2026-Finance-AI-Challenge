- 작성일: 2026-08-14
- 상태: **계획 작성 완료 / 2026-08-14 품질검증 실행 완료**
- 입력 기준: `data/raw/README.md`에 기록된 1~9번 원본과 참고 파일 2개
- 목적: 전처리와 결합 전에 원본의 구조, 기간, 키, 결측, 중복, 이상치, 공간 연결성을 검증한다.

## 1. 작업 경계

현재 문서는 실행계획이다. 실행 결과는 `reports/stage2/qa_summary.md`와 같은 폴더의 집계 CSV에 분리해 기록했다.

- 원본 파일을 수정하지 않는다.
- 컬럼명을 실제 파일에서 변경하지 않는다.
- CSV 전체를 한 번에 메모리에 올리지 않는다.
- 결측치 대체, 행 삭제, 이상치 제거, JOIN, 집계, 파생변수 생성은 수행하지 않는다.
- 전체 통계가 필요하면 사용자 승인 후 필요한 컬럼만 `chunksize` 단위로 순차 읽어 집계값만 누적한다.
- 이상 사례 확인은 전체 행 출력이 아니라 건수와 제한된 예시 행만 기록한다.
- 품질검증 결과는 `reports/stage2/`에 기록하고 가공 데이터는 생성하지 않는다.

### 키 검증 원칙

1. 추정매출과 점포 데이터는 `기준년분기 + 상권코드 + 서비스업종코드`가 유일키인지 확인한다.
2. 4~9번 데이터는 `기준년분기 + 상권코드`가 유일키인지 확인한다.
3. 상권 구분 코드는 기본 키 후보에 넣지 않되 동일 상권코드에 여러 상권 구분 코드가 대응하는지 별도로 검사한다.
4. 코드명은 키로 사용하지 않고 코드와 1:1 관계인지 검증한다.
5. 4~9번 상권 공통 데이터를 상권×업종 Panel에 결합할 때는 업종마다 반복되는 `many-to-one` 결합임을 명시한다.

## 5. 다른 집계 단위 파일 처리

### 상권변화지표-자치구

- 기본 키 후보: `기준_년분기_코드 + 자치구_코드`
- 상권코드가 없으므로 상권 단위 Panel에 직접 결합하지 않는다.
- 동일 지표의 서울시·자치구 비교용 후보로만 보존한다.
- 향후 사용하려면 상권코드와 자치구코드의 공식 매핑 근거가 먼저 필요하다.

### 직장인구-상권배후지

- 기본 키 후보: `기준_년분기_코드 + 상권배후지_코드`
- `상권배후지_코드`를 `상권_코드`로 간주하지 않는다.
- 핵심 `직장인구-상권` 파일과 별개 데이터로 관리한다.
- 배후지와 상권의 공식 관계가 확인되기 전에는 Panel Dataset에 결합하지 않는다.

### 공통 처리 규칙

- 파일명이 비슷하다는 이유로 키를 동일하게 해석하지 않는다.
- 자치구·상권배후지 행을 상권 단위 행과 합치거나 이어 붙이지 않는다.
- 핵심 1~9 데이터 검증과 별도 결과표에 기록한다.

## 6. 결측치 검증 계획

### 확인 대상

- 기본 키 후보 컬럼의 결측
- 코드명 컬럼의 결측
- 매출 금액·건수의 결측
- 점포 수·개업·폐업·프랜차이즈 컬럼의 결측
- 인구·시설·아파트 수치 컬럼의 결측
- 공간 데이터의 빈 속성 및 빈 도형

### 계산 방법

1. 필요한 컬럼만 선택해 청크 단위로 읽는다.
2. 컬럼별 `전체 행 수`, `결측 수`, `결측률`만 누적한다.
3. 결측률을 전체뿐 아니라 연도·분기별로 나눠 기록한다.
4. 빈 문자열, 공백, 파싱 실패, 실제 NA를 구분한다.
5. 수치 0은 결측으로 치환하지 않고 별도 0 건수로 기록한다.
6. 결측 행은 자동 삭제하지 않고 제한된 예시 키만 별도 보고한다.

| --- | --- | ---: | ---: | ---: | ---: | --- | --- | --- |

## 7. 중복 검증 계획

### 데이터별 유일키

- 추정매출·점포: 기준년분기 + 상권코드 + 서비스업종코드
- 4~9번 상권 데이터: 기준년분기 + 상권코드
- 영역-상권: 상권코드
- 상권변화지표-자치구: 기준년분기 + 자치구코드
- 직장인구-상권배후지: 기준년분기 + 상권배후지코드

### 확인 항목

1. 유일키별 행 수가 1을 초과하는 키의 수와 비율
2. 완전히 동일한 중복 행과 값이 충돌하는 중복 행의 분리
3. 같은 코드에 여러 이름이 대응하는 사례
4. 같은 이름에 여러 코드가 대응하는 사례
5. 연도별 파일 경계에서 동일 분기가 중복 수록됐는지 여부

중복은 자동 삭제하지 않는다. 원본 집계 단위, 파일 중복 수록, 코드 변경 중 무엇이 원인인지 확인한 후 처리 규칙을 정한다.

## 8. 이상치·논리 오류 검증 계획

### 공통 수치 규칙

- 금액, 건수, 점포 수, 인구 수, 시설 수, 세대 수의 음수 여부
- 정수형 개수 변수에 소수값이 존재하는지 여부
- 비율 변수의 단위와 가능한 범위
- 합계와 하위 구성요소의 관계
- 극단값은 삭제하지 않고 분포와 원본 키를 기록

| --- | --- |

### 통계적 이상치

- 분기·업종별 분포를 먼저 분리한다.
- 중앙값, IQR, 1·5·95·99 분위수를 기록한다.
- 로그 스케일 검토가 필요한 긴 꼬리 금액 변수는 원본값과 로그 요약을 함께 본다.
- 통계적 극단값은 오류로 단정하지 않고 `검토 대상` 플래그만 부여한다.
- 이상치 제거 기준은 모델링 전에 별도 승인한다.

## 9. 상권·업종 코드 일관성 계획

### 상권코드

- 연도·분기별 고유 상권코드 수
- 신규·소멸 상권코드
- 상권코드와 상권명의 1:1 관계 및 이름 변경
- 상권 구분 코드 변화
- 영역-상권 DBF에 없는 상권코드
- 영역-상권에만 있고 분기 데이터에는 없는 상권코드

### 서비스업종코드

- 연도·분기별 고유 업종코드 수
- 신규·소멸 업종코드
- 업종코드와 업종명의 1:1 관계 및 이름 변경
- 추정매출에만 있는 업종코드
- 점포 데이터에만 있는 업종코드

### 결합 가능성

- 추정매출 키 중 점포에 없는 키의 수와 비율
- 점포 키 중 추정매출에 없는 키의 수와 비율
- 분기별 매칭률 변화
- `left join` 기준 테이블 후보와 미매칭 처리 방안

## 10. 공간 데이터 검증 계획

- CPG의 문자 인코딩 확인
- PRJ 좌표계 이름과 EPSG:5181 대응 여부 확인
- DBF 상권코드 유일성
- SHP와 DBF 레코드 수 일치
- 빈 도형, 잘못된 도형, 중복 도형
- 도형 범위가 서울시 인근인지 확인
- 상권코드별 도형 누락

공간 검증 시에도 전체 도형을 화면에 한 번에 그리지 않는다. 메타데이터와 유효성 집계를 먼저 계산하고, 오류 도형만 제한적으로 시각화한다.

## 11. 메모리 제한 실행 방식

### CSV

- 인코딩: 현재 확인된 `cp949`
- 기본 `chunksize`: 100,000행 이하에서 시작
- 검증별 `usecols`로 필요한 컬럼만 읽기
- 청크마다 집계값만 누적하고 원본 행 전체를 보관하지 않기
- 예시 행은 검증 항목별 최대 20건만 보존
- 실제 메모리 사용량을 확인한 뒤 청크 크기 조정

### 공간파일

- DBF 헤더·레코드 수를 먼저 확인
- 도형은 필요한 속성만 포함해 읽기
- 전체 지도 렌더링보다 유효성·경계·누락 집계를 우선
- 오류 도형만 별도 표본으로 렌더링

## 12. 실행 순서

1. 파일 존재·크기·인코딩·헤더 재확인

3. 데이터별 기간과 분기별 행 수 집계
4. 기본 키 결측·중복 검사
5. 코드와 코드명 관계 검사
6. 핵심 수치 결측·0·음수 검사
7. 비율 단위와 논리 합계 검사
8. 추정매출·점포 간 키 매칭률 검사
9. 영역-상권 연결성과 공간 유효성 검사
10. 이상치 분포와 제한 예시 기록
11. 사용할 공통 기간과 처리 규칙 제안
12. 사용자 승인 후에만 전처리 규칙 구현

## 14. Stage 2 완료 Gate

- 각 데이터의 실제 컬럼과 집계 단위를 한 문장으로 설명할 수 있다.
- 2025년 점포 영문 헤더 매핑이 검증됐다.
- 실제 기간과 공통 사용 가능 기간이 확정됐다.
- 키 결측·중복과 코드 변경 관계가 기록됐다.
- 추정매출·점포·영역 연결률이 기록됐다.
- 결측, 0, 음수, 범위 오류, 통계적 극단값을 구분했다.
- 자치구·상권배후지 파일을 상권 데이터와 혼합하지 않았다.
- 원본을 수정하거나 조용히 행을 삭제하지 않았다.
- 전처리 규칙은 검증 결과를 근거로 사용자 승인을 받았다.
