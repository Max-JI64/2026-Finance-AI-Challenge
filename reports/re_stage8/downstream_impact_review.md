# RE Stage 8 후속 단계 영향 검토

## 결론

RE3-RE7의 계산·정책·모델·자격·순위 계약은 변경하지 않았다. RE8은 API·화면·로컬 저장·설명 계층만 추가했다. 모델 재학습, Target 변경, 정책 포트폴리오 변경은 없다.

## RE9에 넘기는 항목

- 노출된 기존 OpenAI API 키는 폐기하고 새 키를 배포 환경변수로만 설정한다.
- 외부 공개 URL과 Health Check를 배포 환경에서 검증한다.
- 8개 고정 가상 페르소나의 입력·정답 계약·Trace를 작성한다.
- 10개 정책 20문항 이상 RAG 평가와 데모 직전 접수상태·공식 링크 재확인을 수행한다.
- 상세 CSV에서 정책 대안까지 자동구성하는 기능은 미구현으로 명세와 제출문서에 유지한다.

## 위험과 Fallback

| 위험 | 현재 처리 | RE9 확인 |
| --- | --- | --- |
| 상권환경 모델 입력 없음 | 사용자 직접 충격률 | 대표 Fallback 페르소나 |
| 정책 현재성 불명 | 자격·접수상태 분리, 확인항목 표시 | 데모 직전 공식 재확인 |
| 로컬 RAG DB 장애 | 구조화 결과·공식 링크 유지 | DB 누락 배포 테스트 |
| OpenAI 장애·키 없음 | 로컬 공식근거 요약 | 새 키로 1회 실호출 |
| Fact-lock 실패 | Luna 답변 폐기 | 실패 Trace 보존 |
| 모바일 폭 | 한 열 전환과 가로 단계탐색 | 실제 배포 URL 재확인 |
