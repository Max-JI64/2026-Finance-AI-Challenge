# RE Stage 8.1 검증 보고서

## Gate 판정

**Gate RE8 재검증 통과.** 실제 사용자 과업 중심 4단계 작업공간에 단계형 상권 지도, 업종 대분류, 만원 입력, 5개 빠른 시연, 다중 대안 그래프와 통합 실행정보 Popup을 반영했다. 공개 배포와 고정 가상 페르소나 검증은 RE9 범위다.

## 데이터와 구현 결과

- 사용자 제공 Shapefile: 1,650행, UTF-8, EPSG:5181
- 현행 서비스 상권목록과 일치: 1,596행, 원본에만 있는 과거 54행 제외
- 지도 속성: 자치구 25개, 자치구·행정동 조합 398개, 위도 `37.434592~37.689821`, 경도 `126.802018~127.173766`, 면적 `1,854~2,462,734㎡`
- 지도 표현: 자치구 25개 집계 원→행정동 집계 원→공식 중심좌표와 면적 반지름의 개별 상권 원, 폴리곤 미사용
- 모델 입력: 2025Q4, 21,333개 상권×업종 행, 1,565개 상권, 업종 62개, 동결 Feature 197개
- API: 13개 Path, 상권 지도와 상권×업종 시나리오 경로 추가
- 화면: 사업장 선택, 재무 입력, 현금 진단, 대안과 실행 4단계
- 재무: 화면 만원 단위 최근 3~12개월 월매출 평균, 현재 현금·필수비용·대출, 세 구간 일정, UTF-8-SIG 한글 CSV 양식
- 결과: 시나리오가 적용된 무대응 수치, 안전현금, 13주 그래프, 6개월 현금·부채, 모든 대안 동시 그래프, 버튼 전용 Popup·통합 실행정보
- RAG: SQLite 공식·검토 청크 227개, 정책 10개, 결정론적 BM25
- Luna: `gpt-5.6-luna`, `store=false`, 근거 밖 숫자·금지주장 폐기, 키 부재 시 로컬 Fallback

## 실제 브라우저 검증

- 현재 코드를 `127.0.0.1:8767`에서 실행해 기존 테스트 서버와 분리했다.
- 첫 화면에는 상권 1,596개 대신 코발트색·흰 외곽 링의 자치구 집계 원 25개만 표시됐고, 각 원 안에 구 이름과 상권 수가 호버 없이 보였다.
- `용산구` 선택 시 서울 전체 398개 행정동을 한꺼번에 그리지 않고 용산구 16개 행정동 중간 원과 55개 상권 목록만 표시했다. 각 중간 원 안에는 동 이름과 상권 수가 상시 표시됐다.
- 용산구 행정동 화면을 동쪽으로 드래그하자 현재 지도 중심에 가까운 강동구 16개 행정동으로 레이어가 교체돼, 다른 구를 탐색할 수 있으면서도 여러 구의 원이 겹치지 않았다.
- 행정동 화면을 두 단계 축소하자 행정동 원 16개가 제거되고 자치구 원 25개로 자동 복귀했다.
- `이태원1동` 선택 시 5개 개별 상권 원·목록으로 세분화됐다.
- 업종 대분류 `외식업`을 선택한 뒤 한식·중식·일식 등 세부 업종 10개가 표시됐다.
- 빠른 시연 `매출이 줄고 있는 가게`를 누르자 `용산구 이태원 관광특구·한식음식점`, 최근 월매출 평균 850만원, 현재 현금 500만원이 입력되고 6개 대안 비교 화면으로 바로 이동했다.
- 대안 범례를 눌렀을 때 선택만 바뀌고 Popup 수는 0개였으며, 초록색 `자세히 보기` 버튼을 누른 뒤에만 Popup이 열렸다.
- Popup에서 실행 전 확인조건·신청기한·준비서류·필요현금·최소 신청금액·문의처와 사이트명이 구분된 공식 링크를 확인했다.
- 데스크톱 어두운 색상모드에서 코발트색 원·짙은 청색 선·흰 외곽 링이 OSM의 녹지·도로·수면과 분리되고 원 안의 흰 라벨이 읽히는지 확인했다. 760px 이하 한 열·가로 스크롤 시연카드 규칙은 CSS 정적 검토를 통과했다.
- 브라우저 Console Error·Warning은 0건이었다. 브라우저 확장 자체 안내 Log 1건만 있었다.

기존 `reports/re_stage8/screens/`의 10개 이미지는 RE8 1차 화면 기록이며 RE8.1 화면 증거로 사용하지 않는다. 최신 브라우저 검증은 위 상호작용 결과와 DOM 수치로 기록했다.

## 보안과 제한

- 로컬 `.env`는 Git에서 제외하며 API 키 원문은 코드·환경예제·로그·DB·Manifest·메모리에 복사하지 않는다.
- 재무 입력은 현재 요청 계산에만 사용하고 AI 요청에 포함하지 않는다.
- 지도는 상권 실제 경계가 아니라 공식 중심좌표에 면적 비례 원을 그린 근사 표현이다.
- 상권×업종 시나리오는 집계 환경 변화율이며 개별 점포의 매출 예측이 아니다.
- 정책 자격과 접수상태는 승인 가능성이 아니며 신청 전 공식기관 확인이 필요하다.
- 채팅에 노출된 키는 보안상 교체를 권장한다. 이 후속 점검에서는 사용자의 명시적 외부호출 승인 없이 Luna 실호출을 추가로 수행하지 않았다.
- 외부 공개 URL, 정책 현재성 재확인, 8개 페르소나 검증은 RE9에 남겼다.

## 2026-08-17 후속 UI 변경 검증 범위

- 서울 전체 상권명 검색, 개별 상권 상시 라벨, 줌 단계별 자치구·행정동·상권 자동 선택, 지역·업종 변경 시 기존 결과 재계산, RAG 동일 URL 근거 묶음을 반영했다.
- 대안 상세 Popup의 바깥 배경 클릭 닫기와 자격 확인 전 정책의 추천 순위 제외 표시, 1순위 대안도 기간 중 현금이 음수이면 최저 현금을 알리는 경고를 반영했다.
- 네 목표를 바꾸면 실행 가능한 대안이 결정론 순위대로 재배치되고 카드의 목표별 판단값과 상세 표 순위가 함께 바뀐다. 여러 목표의 1순위가 같더라도 선택 기준과 판단값은 화면에서 구분된다.
- 카드·그래프에서 다른 대안을 선택하면 상단 유의문도 그 대안의 자격 상태, 13주 최저 현금, 확인 조건으로 즉시 교체되며 이전 1순위의 경고가 남지 않는다.
- `node --check`, `git diff --check`, RE8 집중 테스트 24건을 통과했다. 사용자 요청에 따라 이 후속 변경의 브라우저 시각·상호작용 검증은 수행하지 않았으며 사용자가 직접 확인한다.
