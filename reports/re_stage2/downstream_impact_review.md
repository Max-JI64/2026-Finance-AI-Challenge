# RE Stage 2 종료 환류 — 후속 단계 영향 검토

## 결론

RE2 결과로 RE3의 현금흐름 핵심 계산식은 바꾸지 않는다. 다만 실제 정책 구조가 확인되었으므로 RE4와 RE6의 입력·이벤트 계약을 보강해야 한다.

## RE Stage 3 영향

- 현금흐름 계산에 `공과금`을 기타 고정비와 별도 항목으로도 입력할 수 있게 한다. 바우처가 공과금·4대보험·차량연료비만 감액하기 때문이다.
- 사후정산형 보조금의 선행현금을 검증하려면 일회성 지출에 `expense_type`과 지급일이 필요하다.
- 신용점수·채무조정·폐업이력은 현금흐름 계산 필드가 아니므로 RE3에 섞지 않는다.
- 따라서 RE3 선행조건은 계속 Gate RE1이며, RE2 때문에 착수를 막지는 않는다.

## RE Stage 4 영향

- 같은 정책 안의 하위 상품을 구분하도록 `event_id`를 필수화한다.
- 서울시 육성자금은 하위 자금 선택 전 하나의 평균 금리·한도로 계산하지 않는다.
- `사후정산`, `카드 선차감`, `직접대출`, `대리대출`, `보증·이차보전 연계`를 별도 변환기로 처리한다.
- 다시서기와 서울시 재기지원자금은 연결된 동일 대출을 두 번 더하지 않도록 `linked_event_id` 또는 중복방지 키가 필요하다.
- `미확인`인 지급일·보증조건은 사용자 가정 없이는 금액 이벤트를 만들지 않는다.

## RE Stage 6 영향

- 현금흐름 입력과 별도로 세션 한정 `eligibility_profile`이 필요하다.
- 필수 후보 필드: 소재지, 업종, 개업일, 대표자 연령구간, 2024·2025 및 반기 매출 비교, 2025 연매출 구간, 상시근로자수, 임차·점포형 여부, 휴폐업·폐업예정일, 세금 완납, 재해확인서, 기존 지원이력, 재창업·채무조정·성실상환 상태, 기존 대출 실행일·금리·만기연장 애로.
- 정확한 신용점수 저장 대신 `NCB 839 이하`, `NCB 919 이하`의 사용자 확인형 3상태(`예/아니오/모름`)를 사용한다.
- 사용자 입력만으로 확인할 수 없는 예산잔액·은행심사·보증승인은 `추가 확인 필요`로 반환한다.
- 현재 217개 Chunk에 RE6 필수 Metadata인 정책 버전·원문 URL·해시를 결합한 뒤에만 검색 인덱스를 만든다.

## 계획 변경 여부

| 후속 단계 | 변경 |
| --- | --- |
| RE3 | 공과금·4대보험·차량연료와 일회성 지출 유형을 상세 입력에 추가 |
| RE4 | `event_id`, 연결 이벤트 중복방지, `미확인` 차단 규칙 추가 |
| RE5 | 수정 없음. 정책 구조화 결과가 Target·모델 정의를 바꾸지 않음 |
| RE6 | 세션 한정 자격 프로필과 신용구간 3상태 입력 추가 |
| RE7~RE9 | 현재 수정 없음. RE4·RE6 결과에서 다시 환류 검토 |

이 변경은 정책 범위·Target·모델 선택을 바꾸지 않는다. RE3의 상세 입력 계약은 구현 직전 사용자 승인 Gate에서 확정한다.
