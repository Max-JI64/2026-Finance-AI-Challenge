# RE Stage 9 발표자료용 근거표

| 발표 주장 | 직접 근거 | 안전한 표현 |
| --- | --- | --- |
| 기존 서비스와의 차이 | 지급일·선지출·상환일을 같은 현금축에서 계산 | 정책 목록을 보여주는 데서 끝나지 않고 돈이 들어오고 나가는 시점을 비교한다. |
| 핵심 질문 | 13주·6개월 현금과 부채 동시 계산 | 지원조건 적용 시 돈이 언제까지 버티고 부채가 얼마나 늘어나는가를 보여준다. |
| 대출 편향 방지 | 무대응·비용절감·비차입·대환·신규대출·복합안 동일 지표 | 대출을 우선 권하지 않고 여섯 대응안을 같은 기준으로 비교한다. |
| 정책 선정 이유 | 대표 10개 정책의 56 Rule·30 Event | 정책 수를 넓게 나열하기보다 금융구조가 다른 10개 정책을 깊게 구현했다. |
| 신규대출 Trade-off | 신규 현금과 부채·월상환·총이자 동시 출력 | 당장 현금은 늘지만 미래 상환부담도 함께 늘어나는 모습을 숨기지 않는다. |
| 최소부채 목표 | RE7 사전식 결정론 정렬 | 기본 목표는 신규부채 최소화이며 AI가 순위를 바꾸지 않는다. |
| AI 역할 | LightGBM 시나리오, Hybrid 검색, Luna 설명 | AI는 상권환경 범위와 공식근거 탐색·설명을 돕고 자격·계산·최종 결정은 검수 규칙이 담당한다. |
| 공식 근거 | 정책 ID·버전·기준일·공식 URL, 가정 원장 | 공식값과 사용자 입력·가정값을 구분하고 링크로 되돌아갈 수 있다. |
| 모델 한계 | 집계 상권×업종, 개인 Target 없음 | 개별 가게 미래매출이나 폐업확률이 아니라 상권환경 스트레스 시나리오다. |
| 개인정보 | 비식별 범주형 외부 전송, 원값 비저장 | 주민번호·계좌·사업자번호를 요구하지 않고 원금액과 자격 응답은 외부 검색에 보내지 않는다. |
| 검증 | 8개 고정 페르소나 8/8, 20문항 20/20 | 가상 사업장 기능 일치 검증이며 실제 사용자 만족도나 정책효과 검증은 아니다. |
| Stage 0~6 보존 | 동결 Artifact와 감사 경로 | 기존 결과를 지우지 않고 기준선과 재현 근거로 보존했다. |
| 확장 가능성 | 17개 정책 색인, Rule/Event 분리 | 새 정책도 검수 후 Rule·Event·버전을 추가하는 방식으로 확장할 수 있다. |

## 금지 표현

- AI가 미래를 예측하고 최적 정책을 추천한다.
- 정책 적용으로 매출이 회복된다.
- 정책 또는 대출 승인 가능성을 예측한다.
- 가상 페르소나 결과가 실제 사용자 만족도나 현실 정책효과를 입증한다.
