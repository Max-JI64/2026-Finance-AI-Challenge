# 정책금융 영향 시뮬레이터 기능명세서

## 1. 서비스 목적

서울 소상공인이 아무 조치를 하지 않을 때와 비용절감, 비차입 지원, 대환, 신규 정책자금, 복합 대응을 같은 지급·상환 일정 위에서 비교한다. 핵심 질문은 **지원조건 적용 시 돈이 언제까지 버티고 부채가 얼마나 늘어나는가**이다.

개별 점포의 미래매출·폐업, 신용도, 정책 또는 대출 승인확률을 예측하지 않는다. 정책 수혜의 인과효과를 보장하거나 AI가 최종 대안을 선택한다고 표현하지 않는다.

## 2. 실제 구현범위

| 영역 | 구현상태 | 사용자 출력 |
| --- | --- | --- |
| 사업장 선택 | 구현 | 서울 자치구→행정동→1,596개 상권, 업종 대분류→세부 업종 |
| 재무 입력 | 구현 | 최근 3~12개월 매출, 현금, 비용, 기존 대출, 만원 단위 입력 |
| 현금 진단 | 구현 | 13주·6개월 현금, 고갈일, 안전현금, 하방·기준·회복 범위 |
| 정책 후보발굴 | 구현 | 17개 정책 Hybrid 검색, 후보 이유, 공식 링크 |
| 자격 확인 | 구현 | 공식 Rule, 적격·부적격·추가 확인, 접수상태 분리 |
| 정책 영향 비교 | 구현 | 무대응 포함 6개 기본 대응과 검수 Event 동적 대안 |
| 최종 순위 | 구현 | 최소부채·최장생존·최소상환·빠른실행 결정론 순위 |
| AI 설명 | 구현 | 공식 근거 설명, Fact-lock, 로컬 Fallback |
| 공개 배포 | 미구현 | 플랫폼·계정·URL 사용자 결정 대기 |

## 3. 사용자 이용 흐름

1. 사업장 선택: 상권과 업종, 영업기간을 선택한다.
2. 재무 입력: 최근 매출과 현재 현금, 월 비용, 기존 부채를 입력한다.
3. 현금 진단: 상권환경 스트레스 범위와 13주·6개월 무대응 현금을 확인한다.
4. 대안과 실행: 목표별로 무대응과 여섯 대응안을 비교하고 공식 근거·확인조건·신청정보를 확인한다.

가상 빠른 시연은 실제 사업장 사례가 아니며 상세 일정 기반 검증용 입력임을 표시한다.

## 4. AI 역할

- LightGBM Quantile: 상권×업종 집계단위의 하방·기준·회복 매출환경 변화율을 생성한다.
- OpenAI Embeddings: 공개 정책 Chunk와 승인된 비식별 상황요약의 의미 유사성을 계산한다.
- BM25와 RRF: 정확어 검색과 Vector 순위를 결정론적으로 결합한다.
- GPT-5.6 Luna: 검색된 공식 근거를 설명한다.
- 결정론 코드: 자격판정, 현금·부채 계산, 단계형 질문, 최종 순위를 담당한다.

Embedding과 Luna는 자격, 계산, 순위를 변경하지 못한다. Embedding은 5초 Timeout, 최대 2회 뒤 BM25로 전환한다.

## 5. 입력·출력 데이터

입력은 서울 상권·업종, 최근 월매출, 현재 현금, 월별 필수비용, 기존 대출과 사용자가 직접 확인한 정책 조건이다. 화면 입력은 만원 단위이며 API 전송 전에 원 단위 정수로 변환한다.

출력은 13주·6개월 현금경로, 최저·기말현금, 고갈일, 신규부채, 최대 월상환, 만기 총이자, 자격·접수상태, 확인조건, 공식 링크와 실행계획이다. Rule ID, Chunk ID, 내부 검색점수는 사용자 화면에 노출하지 않는다.

## 6. 개인정보 처리

주민등록번호, 계좌번호, 사업자등록번호, 정확한 신용점수를 필수 입력으로 받지 않는다. 요청·CSV·자격 응답·질문은 서비스 DB, 검색 인덱스, 브라우저 저장소에 영구 저장하지 않는다.

외부 API에는 자치구, 업종 대분류, 매출추세·고정비·부채·현금위험 범주, 사용자 목표와 로컬에서 민감 패턴을 제거한 정책 질문만 전송한다. OpenAI API 데이터는 기본적으로 모델 학습에 사용되지 않지만 기본 악용 모니터링 로그에는 최대 30일 포함될 수 있음을 화면에 고지한다.

## 7. 샘플 입력과 예상 결과

고정 입력은 `data/samples/re_stage9/personas.json`, 입력 Hash와 기대 결과는 `reports/re_stage9/persona_oracle.json`에 보존한다. P02는 기존 대출 8,000만원 중 공식 한도 5,000만원만 부분대환하고 3,000만원은 기존 일정으로 유지한다. P08은 Embedding 2회 실패 뒤 BM25로 전환하며 잘못된 음수 현금 입력은 원문을 반사하지 않는 HTTP 422로 거부한다.

8개 페르소나 모두 기대 행동·핵심 값이 일치했고, 대표 10개 정책의 20개 공식근거 검색 문항이 모두 Hit@5를 통과했다.

## 8. 브라우저·운영 제한

- OSM 지도 타일 또는 외부 JavaScript가 실패해도 목록 입력은 유지한다.
- 계정·세션 저장, 주소 검색, GPS, 실제 상권 폴리곤은 MVP 범위 밖이다.
- 공개 URL, 제출기간 접근, 운영계정 Usage tier와 운영 키는 아직 검증하지 않았다.
- 스크린샷 이미지 분석은 사용자 요청에 따라 RE9 QA에서 수행하지 않는다. 브라우저 QA는 DOM·접근성 구조·계산 결과·반응형 오버플로 상태로 수행한다.

## 9. MVP 한계

상권환경 모델은 개별 가게 매출예측이 아니다. 정책 결과는 승인되지 않음, 지급 지연, 실제 승인금액 변동을 보장하지 않는다. 조건부 후보는 확인 전 기본 순위에서 제외된다. 가상 페르소나 검증은 실제 사용성·만족도·정책 현실 효과의 근거가 아니다.
