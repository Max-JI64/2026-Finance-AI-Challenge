# RE Stage 1 입력·출력 계약 초안

## 간편 입력

| 필드 | 형식 | 단위 | 필수 | 사용처 |
| --- | --- | --- | --- | --- |
| 기준일 | 날짜 | YYYY-MM-DD | 예 | 13주·6개월 일정 생성 |
| 상권 | 코드/명칭 | 서울 상권 | 예 | 집계환경 시나리오 조회 |
| 업종 | 코드/명칭 | 서비스 업종분류 | 예 | 집계환경 시나리오 조회 |
| 현재 현금 | 정수 | 원 | 예 | 시작 현금잔액 |
| 최근 월매출 | 정수 | 원/월 | 예 | 기준 현금유입 |
| 고정비 | 정수 | 원/월 | 예 | 임차료·인건비·공과금 등 |
| 변동비율 | 실수 | 0~1 | 예 | 매출 연동 비용 |
| 기존 월 원리금 | 정수 | 원/월 | 예 | 기존 부채유출 |
| 사용자 충격률 | 실수 | -1~1 | 아니오 | ML Fallback 또는 사용자 시나리오 |
| 안전현금 기준 | 정수 | 원 | 아니오 | 목표 충족 판정; 기본값은 RE3 승인 후 |

## 상세 CSV 입력

필수 열 후보는 `date`, `cash_in`, `fixed_out`, `variable_out`, `debt_service`, `one_off_out`이다. 통화는 원, 날짜는 ISO 형식, 금액은 음수가 아닌 절대액으로 받고 유입·유출 열에서 방향을 구분한다. 확정 스키마와 예제 파일은 RE Stage 3에서 검산용 사례와 함께 승인한다.

## 정책 데이터 입력

| 객체 | 핵심 필드 | 생성시점 |
| --- | --- | --- |
| Policy | 정책 ID·명칭·기관·적용지역·신청기간·원문 URL | RE2 |
| Eligibility Rule | 조건·연산자·기준값·근거 조항·미확인 처리 | RE2·RE6 |
| Financial Event | 유형·금액·지급일·자부담·금리·거치·상환 | RE4 |
| RAG Chunk | 원문 문장·문서·페이지/조항·적용기간 | RE6 |

## 출력

| 출력 | 단위/형식 | 계산 주체 |
| --- | --- | --- |
| 주별 현금잔액 | 원, 13개 시점 | 현금흐름 엔진 |
| 월별 현금잔액 | 원, 6개 시점 | 현금흐름 엔진 |
| 최저 현금잔액 | 원 | 현금흐름 엔진 |
| 현금 고갈 시점 | 날짜 또는 없음 | 현금흐름 엔진 |
| 신규 차입액 | 원 | 정책 금융 이벤트·비교 엔진 |
| 월 원리금·총이자·총상환 | 원 | 현금흐름 엔진 |
| 지원금·비용감면 | 원 | 정책 금융 이벤트 |
| 자격상태 | 적격/부적격/추가확인 | 규칙 엔진 |
| 공식 근거 | 문서·조항·URL·확인일 | RAG |
| 실행순서 | 단계 목록 | 비교 엔진, LLM 설명 |

## 안전한 실패

- 필수값 누락 또는 단위 오류 시 계산을 중단하고 해당 필드를 표시한다.
- 정책 원문이 없거나 조건이 충돌하면 `추가확인`으로 반환한다.
- 공식 금액·지급시점이 없으면 임의 값을 생성하지 않고 계산 불가 사유를 반환한다.
- LLM 출력은 결정론적 계산값과 자격상태를 변경할 수 없다.
