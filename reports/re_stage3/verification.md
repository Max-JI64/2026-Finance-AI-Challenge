# RE Stage 3 검증 기록

## 구현 결과

- 엔진 버전: `re3-v1`
- 간편 입력과 상세 CSV 입력을 분리했다.
- 동일 현금 이벤트 원장을 13개 주 구간과 6개 월 구간으로 집계한다.
- 계산된 음수 현금을 보존한다.
- 간편 대출상환액은 원금·이자 합계로만 처리하고 잔여원금·총이자를 추정하지 않는다.
- 상세 대출은 원금균등·원리금균등·만기일시상환, 거치기간, 월 이자, 원 단위 반올림을 지원한다.
- 외부 데이터, 정책, ML, RAG, LLM을 사용하지 않았다.

## 손계산·결정론 검증

`scripts/verify_re_stage3.py`를 실제 Python 3.13.1 환경에서 실행했다.

- 결과: `RE_STAGE3=PASSED checks=26/26`
- 13개 주별 기말현금 전부와 6개 월별 기말현금 전부를 고정 손계산값과 대조했다.
- 첫 달 매출, 고정비, 변동비, 공과금, 합산 부채상환액과 13주·6개월 말 현금을 대조했다.
- 같은 91일을 포함하는 13주 결과와 첫 3개 월 결과의 기말현금이 일치했다.
- 세 상환방식 모두 12회차, 원금합계, 만기 잔여원금 0원을 확인했다.
- 같은 입력의 전체 구조화 결과가 동일함을 확인했다.
- UTF-8-SIG 상세 CSV, 원·만원 단위 경고, 원금·이자 분리 결과를 확인했다.

상세 값은 `manual_check.csv`, `simple_sample_result.json`, `detailed_sample_result.json`, `loan_method_summary.json`에 보존했다. 파일 경로·크기·SHA-256은 `manifest.json`에 기록했다.

## 개인정보 확인

- 입력 스키마에 주민등록번호, 계좌번호, 신용점수, 필수 사업자등록번호가 없다.
- 계산 모듈에는 DB 쓰기와 사용자 원금액 로깅이 없다.
- 프로젝트에 저장된 입력·결과는 가상 샘플뿐이다.
- API·웹 세션 처리와 실제 사용자 입력 비저장 검증은 RE8 통합 범위다.

## 남은 한계

- 간편 입력은 월 반복값을 지정일에 배치하므로 실제 일별 매출 변동을 표현하지 않는다.
- 상세 입력은 사용자가 미래 예정 이벤트를 날짜별로 제공해야 하며, 과거 매출로 미래 일정을 추정하지 않는다.
- 같은 날짜 안의 시간순서는 없고 일말 순현금으로 고갈 여부를 판단한다.
- 이자는 월 단위이며 실제 금융기관의 일수계산·중도상환·수수료 규칙을 대신하지 않는다.
- 정책 금융 이벤트 적용은 RE4, 실제 API·세션 비저장은 RE8에서 검증한다.
