## 1. MVP 구현 범위

버팀AI는 현재 재무상태를 기준으로 아무 정책도 이용하지 않을 때와 최대 3개 정책 대안을 각각 적용했을 때의 13주 현금흐름, 6개월 부채와 상환 부담을 같은 일정에서 비교하도록 구현한 웹서비스다. 사용자가 서울 상권·업종, 최근 매출, 보유 현금, 비용과 대출을 입력하면 13주 현금흐름과 6개월 부채를 계산한다. 이후 사용자가 고른 최대 3개 정책의 지급액과 지급 시점, 자부담, 금리, 상환조건을 같은 일정에 적용해 첫 현금 부족 시점, 13주차 현금, 6개월 뒤 남은 부채, 월 최대 상환액과 만기까지 총이자를 무대응 결과와 비교한다. 정책 후보는 2026년 8월 17일까지 확인해 서비스에 등록한 공식 공고 가운데 현금 확보, 대출 부담 완화, 운영비 절감, 재기·전환 관련 정책에서 찾는다.

사용자는 재무정보를 입력하기 전에 `대표 사례 30초 보기`에서 고정 가상 음식점의 결과를 확인할 수 있다. 이 화면은 같은 금융 계산 엔진으로 산출한 무대응, 비차입 지원과 신규 정책자금의 첫 현금 부족 시점, 13주차 현금, 6개월 뒤 남은 부채와 상환 부담을 한 번에 보여준다.

서비스는 회원가입 없이 이용할 수 있으며 `진단 → 비교 → 준비`의 세 단계로 구성된다. 화면 상단에서는 다크모드와 화이트모드를 전환할 수 있으며, 선택한 테마는 같은 브라우저에 저장된다. 진단 단계에서는 상권·업종별 하방·기준·회복 매출 변화 참고 범위와 13주 현금, 앞으로 28일 동안 필요한 현금, 6개월 현금과 부채를 확인한다. 비교 단계에서는 정책 후보를 최대 3개까지 고르고 무대응과 정책별 조건부 결과를 비교한다. 준비 단계에서는 정책별 자격 검토 조건과 서비스에 등록된 공고의 신청정보를 확인하고 공식 공고와 신청 경로로 이동한다.

생성형 AI는 서비스에 등록된 공식 공고의 핵심정보를 항목별로 정리하고, 사용자의 정책 질문에 공식 근거 범위에서 답한다. 자격 상태, 정책 적용 금액, 현금흐름, 부채, 정책 효과와 확정 비교 순위는 공식 규칙, 정책 지급·상환 일정과 금융 계산 엔진이 산출한다. 외부 AI를 사용할 수 없어도 재무 진단과 정책 비교는 수행된다.

## 3. 사용자 이용 흐름

### 1단계. 진단

1. 사용자가 공개 URL에 접속한다. 회원가입은 필요하지 않으며, `대표 사례 30초 보기`에서 가상 음식점의 무대응·비차입 지원·신규 정책자금 결과를 먼저 확인하거나 `내 사업장으로 계산하기`로 이동할 수 있다.
2. 서울 상권·업종과 해결 목적을 고르고 최근 3~12개월 매출, 보유 현금, 월 비용과 기존 대출을 입력한다. 목적을 고르기 어렵다면 `무엇부터 확인할지 모르겠음`을 유지할 수 있다. 거래내역 CSV와 대출 일정 CSV는 선택 사항이다.
3. 필수값이 빠졌거나 형식이 맞지 않으면 남은 필수 입력 수와 첫 오류 항목을 안내한다. 비용이나 대출이 없다고 사용자가 확인한 경우에만 0원을 입력하며, 계산 전 입력 원장에서 금액과 입출금 시기를 확인한 뒤 진단을 시작한다.

### 상권환경 모델의 적용

학습 단위는 `분기 × 서울 상권 × 서비스업종`이다. 예측 대상은 ① 다음 1분기 매출의 전년 동기 대비 증감률과 ② 다음 2분기 합산 매출의 전년 동기 대비 증감률이다.

Quantile 회귀는 하나의 평균값 대신 결과 분포의 여러 분위점을 예측하는 방법이다. 이 모델은 P10, P50, P90을 산출한다. P10은 낮은 쪽 10번째 백분위, P50은 중앙값, P90은 높은 쪽 90번째 백분위이며, 화면에서는 이를 이해하기 쉽게 `하방·기준·회복`으로 표시한다. 세 값은 개별 점포의 매출 확률이나 예측구간이 아니라 같은 상권·업종의 매출환경을 가정하기 위한 참고값이다.

13주 계산에는 다음 1분기 증감률을, 6개월 계산에는 다음 2분기 합산 증감률을 사용자의 매출 유입 일정에 적용한다. 금융 계산 엔진은 여기에 보유 현금, 비용, 기존 대출 상환과 정책 지급·상환 일정을 더해 각 주차의 예상 현금잔액과 6개월 부채·상환 부담을 계산한다. 따라서 모델이 주차별 현금이나 개별 사업장의 매출을 직접 예측하지 않는다.

미래 정보가 학습에 섞이지 않도록 학습기간을 점차 늘려 가는 expanding-window 방식으로 4개의 시간순 Fold를 구성하고, 2024년 1분기부터 4분기까지를 차례로 검증했다. 각 검증 분기 바로 전 1개 분기는 학습에서 제외해 미래 매출정보의 누수를 막았다.

계절 단순값, 업종별 중앙값과 여러 Quantile 회귀모델을 비교하고, 평균 오차, 분위수 오차, P10~P90 포함률, 구간 폭과 Fold·업종별 안정성을 함께 검토해 LightGBM Quantile을 선택했다. 선택한 모델을 고정한 뒤 2025년 2분기 입력과 2025년 3~4분기 결과를 사용해 한 차례 내부 시간 홀드아웃 평가를 수행했다. 다만 이는 새로운 미래기간을 이용한 독립검증은 아니며, 이후 분기를 이용한 독립검증은 후속 과제로 남아 있다.

사용자가 입력한 매출, 현금, 비용과 대출은 모델 학습에 사용하지 않고 해당 사업장의 금융 결과를 계산할 때만 사용한다.

- 정책 후보와 상담의 근거를 찾기 위한 내부 공고 검색자료와 검증을 통과한 신청정보

### 금융 안전장치

- 생성형 AI와 외부 검색은 자격, 정책 금액, 금융 결과와 비교 순서를 결정하거나 수정할 수 없다.
- 조건이 확인되지 않은 정책은 조건부로 표시하고 금액과 조건이 확인된 대안의 순위에서 제외한다.
- 등록 공고의 인용문과 숫자 근거가 맞지 않으면 해당 값을 표시하지 않고 공식 공고 확인으로 전환한다.
- 정책 효과는 승인되고 화면에 표시된 시점과 조건으로 실행된 경우를 가정한 계산값이다.
- 정책 승인 가능성, 개별 점포 매출, 부도·폐업 가능성과 정책의 인과 효과는 예측하지 않는다.

### 개인정보 처리와 외부 전송

- 주민등록번호, 사업자등록번호, 계좌번호, 카드번호와 개인 신용점수를 입력 필드로 수집하지 않는다.
- 사용자 재무 입력과 정책별 답변은 현재 브라우저 탭에만 유지되고 계산 요청 동안 서버에서 일시적으로 처리된다. 서비스 데이터베이스와 검색자료에는 장기 저장하지 않는다.
- 서비스 이용 중 서버에 새로 저장되는 데이터는 등록된 공개 공고의 검증된 분석 결과뿐이다. 사용자 재무값, 정책별 답변과 상담 대화는 포함하지 않는다.
- 가정 변경 비교는 사용자가 동의한 가정 문장만 외부 OpenAI API에 보낸다. 월매출, 현금, 비용, 대출의 입력 원장과 계산 결과는 요청에 붙이지 않는다.
- 정책 상담은 금액, 전화번호, 계좌 형식, 사업자번호, 주민번호, 상호·업체명, 주소와 상권명 패턴을 제거한 질문·대화와 검색된 공식 근거만 외부 OpenAI API에 보낸다.
- 공고 내용을 정리할 때는 서비스에 등록된 공개 공고만 외부 OpenAI API에 보내며 사용자 재무정보와 정책별 답변을 포함하지 않는다.
- 외부 OpenAI API에는 응답 저장을 요청하지 않는다. 다만 [OpenAI API 데이터 제어 안내](https://developers.openai.com/api/docs/guides/your-data#data-retention-controls-for-abuse-monitoring)에 따르면 기본 악용 모니터링 로그에 입력과 출력이 최대 30일 포함될 수 있다.
- 기관 전송, 자동 신청과 금융상품 계약은 수행하지 않는다.

### 확인할 제한사항

- 상권환경 결과는 상권·업종 집계 단위의 참고 범위다. 개별 점포 매출, 정책 승인 가능성, 부도나 폐업 가능성을 예측하지 않는다.
- 정책별 결과는 화면에 표시된 시점과 조건으로 정책이 승인·실행된 경우를 가정한 조건부 계산이다. 서비스 기준 자격 상태도 최종 자격이나 승인을 뜻하지 않는다.
- 서비스에 등록된 대표 정책과 공식 공고를 사용하므로 현재 접수 여부, 잔여 예산과 최신 변경사항은 공식기관에서 다시 확인해야 한다.
- 사용자가 재무정보를 직접 입력하며 계좌·카드·POS 자동 연동, 신청서류 업로드와 OCR은 지원하지 않는다.
- 사용자 계정, 알림과 재무정보 장기 저장을 제공하지 않으며 기관 전송, 자동 신청과 금융상품 계약을 수행하지 않는다.
- 현재 검증은 기능과 계산 결과의 재현 여부를 확인한 것이다. 실제 사용성, 정책 신청 성과, 매출 개선, 폐업 감소와 정책 효과의 인과관계는 검증하지 않았다.

## 편집 메모: 화면 촬영 공통 기준

이 절은 최종 HWPX에 넣지 않는다.

- 공개 서비스에서 실제 개인정보가 아닌 대표 사례나 발표용 가상 입력만 사용한다.
