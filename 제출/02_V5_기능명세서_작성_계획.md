# V5 기능명세서 작성 계획

## 1. 이 문서의 역할

이 문서는 공식 양식 `(첨부2) 2026 금융 AI Challenge 기능명세서.hwpx`를 다른 세션에서 작성하기 위한 실행 계획이다. 완성 기능명세서가 아니며 공식 HWPX 원본을 수정하지 않는다.

사용자가 한글에서 작성하고 PDF로 변환한다. Codex가 다음 세션에서 맡을 범위는 배포된 V5와 문서의 일치 확인, 항목별 원고 초안, 검증 절차와 예상 결과 정리, 한계와 개인정보 경계 점검이다.

권장 파일 구분은 다음과 같다.

- 원본 보존: `(첨부2) 2026 금융 AI Challenge 기능명세서.hwpx`
- 사용자 작성본: `(첨부2) 2026 금융 AI Challenge 기능명세서_버팀AI_V5_작성본.hwpx`
- 최종 제출본: `(첨부2) 2026 금융 AI Challenge 기능명세서_버팀AI_V5.pdf`

## 2. 확인된 공식 양식

양식에는 팀명, 구성원 성명과 다음 5개 필수 항목이 있다.

1. MVP 구현 범위
2. 주요 기능 목록
3. 사용자 이용 흐름
4. AI 및 데이터 처리 방식
5. MVP 검증 방법

기능명세서는 미래 계획보다 현재 배포 URL에서 실제로 작동하는 범위를 증명하는 문서다. 미구현 기능, 내부 계획, V6 후보와 자동 신청은 제외한다.

## 3. 작성 전에 확정할 입력

- 데이콘에 등록된 정확한 팀명
- 팀장과 팀원 성명 및 순서
- 기획서에서 승인된 최종 서비스명
- 제출할 공개 URL
- 문서 마감 시점의 Cloud Run 상태와 배포 리비전
- 심사자 검증에 사용할 대표 경로와 샘플
- 사용자 최종 확인이 끝난 데스크톱·모바일 범위

현재 기록된 공개 URL은 다음과 같다.

`https://finance-ai-challenge-232883421735.asia-northeast3.run.app`

이 URL은 계획 작성 시점의 값이다. 최종 명세서에 넣기 직전에 루트, `/health`, 대표 사례와 핵심 흐름을 다시 확인한다.

## 4. 문서 작성 원칙

1. `구현됨`, `조건부로 구현됨`, `미구현`을 구분한다.
2. 화면에서 확인할 수 있는 사용자 기능을 중심으로 작성한다.
3. 내부 모듈명은 AI와 데이터 처리 방식을 설명할 때만 쓴다.
4. 수치와 정책 결과는 생성형 AI가 아니라 규칙·Event·현금흐름 엔진에서 나온다는 점을 유지한다.
5. 저장 공고 기준일과 현재 접수 상태의 차이를 숨기지 않는다.
6. 테스트 결과와 실제 화면의 시각 승인을 구분한다.

### 5.1 MVP 구현 범위

목표는 V5가 어디서 시작해 어디서 끝나는지 한 번에 알 수 있게 하는 것이다.

권장 범위 문장:

> 서울 상권·업종과 사용자의 최근 매출, 보유 현금, 비용, 대출을 바탕으로 13주 현금과 6개월 부채를 진단하고, 무대응과 사용자가 선택한 최대 3개 정책의 조건부 금융효과를 비교한 뒤, 정책별 자격조건과 저장 공고의 신청정보를 확인해 공식 신청 경로로 연결하는 웹 MVP다.

구현 범위에 포함할 내용:

- 회원가입 없는 웹 접속
- 선택형 30초 가상 대표 사례
- 상권·업종 및 재무 입력
- 하방·기준·회복 상권환경 시나리오
- 13주 현금, 앞으로 28일 필요현금과 6개월 현금·부채 진단
- 정책 후보 확인과 최대 3개 선택
- 무대응 대비 정책별 현금·부채·상환 부담 비교
- 제한된 AI What-if
- 선택 정책별 조건 입력과 자격·효과 재계산
- 저장 공고 핵심정보 6개 구조화와 근거 검증
- 선택 정책 범위의 정책 상담과 공식 공고 링크

명시적으로 제외할 내용:

- 실시간 공고 크롤링과 접수 상태 보장
- 정책 승인 가능성 예측
- 개인 매출·부도·폐업 확률 예측
- 계좌·카드·POS 자동 연결
- 신청서류 업로드와 OCR
- 장기 사용자 계정, 알림과 재무정보 영구 저장
- 기관 전송과 자동 신청
- 정책 효과의 인과 검증

### 5.2 주요 기능 목록

양식 지시에 맞춰 `기능명, 기능 설명, 관련 화면, 구현 상태` 표로 작성한다. 권장 기능 단위는 다음과 같다.

| 번호 | 기능명 | 명세서에 쓸 핵심 설명 | 관련 화면 | 상태 |
| --- | --- | --- | --- | --- |
| F-01 | 대표 사례 30초 보기 | 고정 가상 음식점의 무대응·비차입 지원·신규 정책자금 결과를 현재 금융 엔진으로 계산 | 첫 화면 | 구현 |
| F-02 | 사업장·재무 입력 | 상권·업종, 최근 3~12개월 매출, 보유 현금, 비용과 대출 입력. 붙여넣기와 0원 단축 제공 | 진단 입력 | 구현 |
| F-03 | 상권환경 및 현금 진단 | 하방·기준·회복 범위와 13주 현금, 28일 필요현금, 6개월 현금·부채 표시 | 진단 결과 | 구현 |
| F-04 | 해결 목적과 검토 계획 | 현금 생존·부채 부담·비용 절감·정책 유형 비교에 맞춰 검토 순서와 지표 표시 순서 조정 | 진단 결과 | 구현 |
| F-05 | 정책 후보 선택 | 추가 사전 질문 없이 정책 후보를 보여주고 최대 3개를 비교 대상으로 선택 | 진단 결과 | 구현 |
| F-06 | 무대응 대비 정책 비교 | 13주 현금 그래프와 현금·부채·월 상환·이자 차이를 정책별로 확인 | 비교 | 구현 |
| F-07 | AI What-if | 동의한 가정 문장만 해석해 매출·비용·범위·비교기준을 임시로 바꿔 재계산 | 비교 | 조건부 구현 |
| F-08 | 정책별 준비 조건 | 선택 정책의 전체 검수 조건을 예·아니오·모름 또는 값으로 입력하고 같은 화면에서 상태와 효과 재계산 | 준비 | 구현 |
| F-09 | 공고 핵심정보 확인 | 저장 공고에서 신청 기간·금융 조건·신청 경로·필요 서류·문의처·게시일을 구조화하고 검증된 값만 표시 | 준비 | 조건부 구현 |
| F-10 | 정책 상담과 공식 인계 | 선택 정책의 공식 공고 범위에서 최대 5회 질의응답하고 공식 공고와 신청 경로로 이동 | 준비 | 조건부 구현 |

`조건부 구현`의 의미를 표 아래에 설명한다.

- F-07은 사용자가 외부 AI 전송에 동의한 가정 문장만 AI로 해석한다. 동의하지 않거나 외부 AI가 없으면 지원 범위 안내 또는 정해진 경로를 사용한다.
- F-09와 F-10은 저장된 공개 공고와 외부 AI 상태에 영향을 받는다. 실패하면 값을 추정하지 않고 공식 공고 직접 확인으로 닫는다.
- 핵심 재무 진단과 정책 비교는 외부 AI가 없어도 수행할 수 있다.

기능 수는 양식 공간에 맞춰 F-01부터 F-10을 묶을 수 있다. 묶더라도 대표 사례, 진단, 비교, 준비, 공고 확인의 다섯 사용자 기능은 빠뜨리지 않는다.

### 5.3 사용자 이용 흐름

목표는 심사자가 배포 URL에서 그대로 따라 할 수 있는 순서를 쓰는 것이다.

권장 기본 흐름:

1. 공개 URL에 접속한다. 회원가입이나 계정은 필요하지 않다.
2. `대표 사례 30초 보기`를 선택해 가상 음식점의 세 대안을 먼저 보거나 바로 `내 사업장으로 계산하기`로 이동한다.
3. 상권과 업종을 선택하고 최근 매출, 보유 현금, 비용과 대출을 입력한다.
4. 해결 목적을 고르거나 기본값 `무엇부터 확인할지 모르겠음`의 제안을 확인한다.
5. 하방·기준·회복 상권환경과 13주 현금, 28일 필요현금, 6개월 현금·부채 결과를 확인한다.
6. 질문 게이트 없이 표시되는 정책 후보 중 최대 3개를 선택한다.
7. 비교 화면에서 무대응과 선택 정책의 13주 현금 그래프와 현금·부채 차이를 정책별로 확인한다.
8. 필요하면 AI What-if로 매출, 비용 또는 상권 범위를 임시 변경하고 적용 전후 결과를 비교한다.
9. 한 정책의 준비 화면으로 이동해 연결된 자격조건을 직접 선택한다.
10. 조건 선택 뒤 같은 화면에서 자격 상태와 계산 가능한 조건부 효과를 다시 확인한다.
11. 저장 공고의 신청정보 6개와 근거 상태를 확인한다.
12. 현재 접수 여부와 최종 자격은 공식 공고에서 다시 확인하고 공식 신청 경로로 이동한다.

세 단계 요약은 문서와 화면에서 동일하게 쓴다.

| 정책 상담 | 선택 정책과 질문 | 공식 공고 범위 검색·설명 | 근거 기반 답변 | 자격·승인 확정 불가 |

#### 사용 데이터

- 서울 상권·업종 집계 데이터와 학습된 시나리오 모델
- 사용자가 입력하는 최근 월매출, 보유 현금, 비용과 대출
- 선택형 거래내역·대출 CSV
- 공식 정책 공고, 구조화 Rule과 정책 Event
- 저장 공고 검색 인덱스와 구조화 캐시

#### 개인정보와 외부 전송

- 사용자 재무 입력은 계산 중 서버 메모리에서 처리할 수 있지만 장기 저장하지 않는다.
- 브라우저의 현재 입력과 선택 상태는 세션 범위에서만 유지한다.
- 공개 공고 구조화 캐시에 사용자 재무정보를 넣지 않는다.
- 외부 AI에는 사용자가 동의한 What-if 문장 또는 공개 저장 공고만 보낸다.
- 월매출, 현금, 비용, 대출과 계산 결과는 외부 AI에 보내지 않는다.
- 주민등록번호, 사업자등록번호, 계좌번호, 카드번호와 개인 신용점수를 수집하지 않는다.

### 5.5 MVP 검증 방법

이 항목은 `접속 방법, 샘플 입력, 예상 결과, 실행환경, 제한사항`을 모두 포함해야 한다.

#### 검증 경로 A: 가장 빠른 대표 사례

1. 공개 URL 접속
2. `대표 사례 30초 보기` 선택
3. `현금 부족과 기존 부채가 함께 있는 가상 음식점` 표시 확인
4. 무대응, 비차입 지원, 신규 정책자금 세 열 확인
5. 첫 현금 부족 주차, 13주차 현금, 6개월 뒤 남은 부채, 월 최대 상환액과 총이자 확인
6. 비차입 지원의 신규 부채 0원과 신규 정책자금의 부채 증가 표시 확인
7. `내 사업장으로 계산하기`를 눌러 진단 입력으로 이동

정확한 금액과 주차는 문서 마감 시 다음 엔드포인트의 현재 응답으로 채운다.

`/api/v5/representative-demo`

숫자를 기억이나 예시 문서에서 옮기지 않는다. 최종 배포 엔진의 응답을 한 번 저장해 기능명세서 예상 결과와 화면 숫자를 대조한다.

#### 검증 경로 B: 전체 사용자 흐름

발표용 입력 프리셋은 다음 경로에서만 보인다.

`/?demo=1`

이 경로는 입력값만 채우고 목적 선택, 계산과 정책 선택을 자동 실행하지 않는다. 최종 명세서에서는 사용할 프리셋 한 개를 정하고 다음 값을 기록한다.

- 프리셋 이름
- 상권과 업종
- 최근 매출
- 보유 현금과 비용
- 대출 조건
- 선택 해결 목적
- 선택 정책
- 예상 13주·6개월 핵심 결과

권장 대표 경로는 `매출이 줄고 있는 가게` 또는 `대출 상환이 부담인 가게`다. 어느 경로를 제출 검증 사례로 쓸지는 최종 화면과 계산 결과를 본 뒤 사용자가 확정한다.

#### 자동 검증 근거

현재 기록:

- V5 전용 회귀 18/18 통과
- V4·관련 공용 정책 회귀 83/83 통과
- 검토 렌즈 Oracle 25/25
- 사용자 흐름 8/8
- JavaScript 문법 2/2
- 정적 자산 링크 7/7

근거 파일은 [`v5/VERIFICATION.md`](../v5/VERIFICATION.md)와 [`reports/v5/evaluation/`](../reports/v5/evaluation/)이다. 최종 문서 작성 세션에서는 변경 파일과 배포 상태를 확인한 뒤 필요한 검증만 다시 수행한다. 과거 로컬 PID와 주소는 제출 문서에 넣지 않는다.

#### 실행환경

최종 확인 뒤 다음처럼 간단히 쓴다.

- 별도 계정 없음
- JavaScript가 활성화된 최신 데스크톱 Chrome 또는 Edge 권장
- 공개 Cloud Run URL 사용
- 첫 접속은 최소 인스턴스 0 설정에 따라 시작 시간이 걸릴 수 있음
- 모바일 지원을 쓸 경우 사용자가 실제 기기 또는 브라우저에서 확인한 범위만 명시

#### 제한사항

- 상권 시나리오는 상권·업종 집계환경이며 개인 매출 예측이 아님
- 정책 효과는 승인과 표시된 시점의 실행을 가정한 조건부 계산
- 저장 공고 기준이므로 현재 접수 여부, 잔여 예산과 최신 변경은 공식기관에서 재확인
- 최종 자격과 승인은 신청기관이 판단
- 정책 비교는 선정된 대표 10개 정책 범위
- 사용자 재무정보를 장기 저장하지 않음
- 자동 신청, 기관 전송과 금융상품 계약을 수행하지 않음
- 실제 사용자 수요, 신청 성과와 정책 인과 효과는 검증하지 않음

## 6. 화면 이미지 계획

기능명세서는 관련 화면을 요구하므로 다음 다섯 장면을 우선한다.

1. 첫 화면과 대표 사례
2. 재무 입력과 입력 부담 완화 기능
3. 13주 현금 진단과 정책 후보
4. 무대응 대비 정책 비교
5. 정책별 준비 조건과 공고 핵심정보

필요하면 AI What-if 또는 정책 상담을 여섯 번째 보조 화면으로 추가한다. 화면 이미지는 공개 배포본과 합성 입력을 사용하며 실제 개인정보를 넣지 않는다.

각 이미지에는 `화면 번호, 기능명, 사용자가 확인할 핵심`만 짧게 붙인다. 코드나 내부 API 응답 화면을 사용자 기능 이미지로 대신하지 않는다.

기본 역할 분담은 다음과 같다.

- Codex: 기능별 캡처 목록, 필요한 화면 상태와 입력 경로, 권장 구도, 화면 번호와 캡션 초안을 준비한다.
- 사용자: 공개 배포 사이트에서 대표 사례나 발표용 가상 입력으로 직접 캡처하고 HWPX에 삽입한 뒤 크기, 자르기와 표 배치를 조정한다.
- Codex: 변환된 PDF를 전달받으면 기능 설명과 화면의 일치, 숫자·캡션 누락, 글자와 이미지 잘림 가능성을 점검한다.
- 사용자: 최종 화면 품질과 PDF 시각 승인을 담당한다.

사용자가 별도로 요청하면 Codex가 배포 사이트의 원본 캡처 파일 생성을 도울 수 있다. 다만 HWPX 삽입과 최종 배치는 사용자가 직접 하는 것을 기본으로 한다.

## 7. 다른 세션의 실행 순서

1. 이 계획, 공식 HWPX, `v5/README.md`, `V5 사용자 경험 흐름.md`, `v5/VERIFICATION.md`를 읽는다.
2. 팀명, 구성원, 서비스명과 제출 URL을 사용자에게 확인한다.
3. 공개 URL의 루트, `/health`, 대표 사례와 전체 흐름을 현재 시점에 재확인한다.
4. 기능 목록을 실제 화면과 API에 대조하고 상태를 `구현` 또는 `조건부 구현`으로 확정한다.
5. 대표 사례 API의 현재 숫자를 검증 경로 A의 예상 결과로 기록한다.
6. `/?demo=1`의 프리셋 한 개를 사용자와 선택하고 전체 흐름의 입력과 예상 결과를 기록한다.
7. AI·데이터 처리표와 개인정보 경계를 현재 코드에 대조한다.
8. 제한사항이 기획서와 서비스 화면의 문구와 같은지 확인한다.
9. 사용자에게 HWPX 입력용 최종 원고와 캡처 목록·입력 경로·구도·캡션을 항목별로 전달한다.
10. 사용자가 공개 배포 사이트에서 대표 사례 또는 발표용 가상 입력으로 화면을 캡처한다.
11. 사용자가 원고와 화면 이미지를 HWPX 작성본에 직접 넣고 표와 페이지 배치를 조정한다.
12. 사용자가 PDF로 변환한다.
13. 변환 PDF에서 표 넘침, 이미지 해상도, 캡션, URL 줄바꿈, 항목 누락과 페이지 순서를 사용자와 함께 확인한다.
