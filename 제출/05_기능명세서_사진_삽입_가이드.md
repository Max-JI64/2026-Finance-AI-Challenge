# 기능명세서 사진 삽입 가이드

이 문서는 공식 기능명세서 원고에 넣을 서비스 화면과 처리 구조도의 캡처 상태, 삽입 위치, 자르기 범위와 캡션을 정리한 편집용 가이드다. 이 안내문 자체는 공식 HWPX에 붙여 넣지 않는다.

## 1. 최종 권장 구성

기능명세서에는 다음 6개 그림을 권장한다.

| 그림 | 내용 | 우선순위 | 연결 기능 |
| --- | --- | --- | --- |
| 그림 1 | 대표 사례 금융결과 비교 | 필수 | F-01 |
| 그림 2 | 사업장·재무 입력과 입력 원장 | 필수 | F-02 |
| 그림 3 | 13주 현금 진단과 정책 후보 | 필수 | F-03, F-04, F-05 |
| 그림 4 | 무대응 대비 선택 정책 비교 | 필수 | F-06, F-07 |
| 그림 5 | 정책별 자격조건과 공고 핵심정보 | 필수 | F-08, F-09, F-10 |
| 그림 6 | AI·데이터 처리 파이프라인 | 필수 | AI 및 데이터 처리 방식 |

페이지가 부족하면 그림 2를 먼저 제외하고 그림 1, 3, 4, 5, 6의 다섯 장으로 줄인다. 기능명세서에서는 장식 이미지보다 실제 기능이 작동하는 화면을 우선한다.

## 2. 공통 캡처 원칙

- 공개 서비스 `https://finance-ai-challenge-232883421735.asia-northeast3.run.app`에서 캡처한다.
- 실제 개인정보를 사용하지 않는다. 대표 사례 또는 발표용 가상 입력만 사용한다.
- 전체 흐름 화면은 같은 가상 입력을 유지한다. 권장 프리셋은 `3. 매출이 줄고 있는 가게`다.
- 발표용 프리셋은 공개 주소 뒤에 `/?demo=1`을 붙여 불러온다. 프리셋은 입력값만 채우므로 해결 목적 선택, 계산과 정책 선택은 직접 진행한다.
- 데스크톱 브라우저는 1440×900 이상, 화면 배율 100%를 권장한다.
- 브라우저 주소창, 북마크, 작업표시줄, 긴 빈 여백과 개발자 도구는 자른다.
- 서비스명, 화면 제목, 핵심 숫자, 그래프 범례, 조건부 고지와 공식 확인 안내는 남긴다.
- 같은 화면을 여러 번 넣지 않는다. 각 그림은 하나의 기능을 증명해야 한다.
- 모든 캡처는 같은 날짜에 만들고 PNG 원본을 보관한다.
- HWPX에서는 이미지 비율을 유지하고 가로폭을 통일한다.
- 캡션에는 `가상 사례` 또는 `가상 입력`이라고 적는다.

## 3. 그림 1. 대표 사례 금융결과 비교

### 삽입 위치

공식 원고의 `1. MVP 구현 범위`에서 서비스가 13주 현금과 6개월 부채를 비교한다고 설명한 문단 다음에 넣는다.

### 캡처 순서

1. 공개 서비스 첫 화면에서 `대표 사례 30초 보기`를 누른다.
2. `현금 부족과 기존 부채가 함께 있는 가상 음식점` 제목이 표시될 때까지 기다린다.
3. 무대응, 비차입 지원, 신규 정책자금의 세 열이 모두 보이게 한다.
4. 첫 현금 부족 시점, 13주차 현금, 6개월 뒤 남은 부채, 월 최대 상환액과 만기까지 총이자 행을 포함한다.
5. `가상 사례`, `내 사업장 결과가 아닙니다`와 조건부 계산 안내가 보이는지 확인한다.

### 권장 자르기

`가상 사례` 표시부터 비교표 하단의 한계 안내까지 자른다. 첫 화면의 긴 서비스 소개와 하단의 개인 진단 버튼은 제외해도 된다. 표 안의 위험색, 성공색과 주의색이 구분되는 크기를 유지한다.

### 캡션

> 그림 1. 무대응, 비차입 지원과 신규 정책자금의 13주 현금 및 6개월 부채 비교(가상 사례)

### 이 그림이 증명하는 내용

정책 목록만 제공하는 것이 아니라, 정책 이용 뒤 현금위기 완화와 부채·상환 부담의 변화를 같은 기준에서 계산한다는 점을 보여준다.

## 4. 그림 2. 사업장·재무 입력과 입력 원장

### 삽입 위치

공식 원고의 `2. 주요 기능 목록` 표에서 F-02 사업장·재무 입력 설명 다음에 넣는다.

### 캡처 순서

1. 공개 주소 뒤에 `/?demo=1`을 붙여 접속한다.
2. `3. 매출이 줄고 있는 가게`를 선택한다.
3. 사업장과 업종, 해결 목적을 선택한 상태를 확인한다.
4. 최근 월매출, 보유 현금, 비용과 대출이 채워진 재무 입력 화면을 캡처한다.
5. 가능하면 `현금 진단 보기`를 누른 뒤 계산 전 입력 원장을 열어 입력값과 시기 가정이 함께 보이는 화면을 두 번째로 캡처한다.
6. 두 화면을 HWPX에서 좌우 2단으로 묶는다.

### 반드시 보일 요소

- 상권과 업종 선택값
- 최근 월매출 입력 영역
- 보유 현금, 임대료, 인건비와 기존 대출 입력 영역
- `임대료 없음`, `직원 없음`, `대출 없음` 중 화면에 표시되는 단축 기능
- 계산 전 입력 원장의 금액과 입출금 시점
- `이 값으로 진단` 또는 입력 수정 행동

### 권장 자르기

입력 화면은 지도 전체보다 선택된 상권·업종과 재무 입력 영역을 중심으로 자른다. 입력 원장은 제목, 핵심 금액과 확인 버튼이 보이도록 자른다. 두 캡처의 높이를 맞춘다.

### 캡션

> 그림 2. 상권·업종과 재무정보 입력 및 계산 전 입력값 확인 과정(가상 입력)

### 이 그림이 증명하는 내용

사용자가 계산에 들어가는 상권, 매출, 현금, 비용, 대출과 시기 가정을 직접 확인한 뒤 진단을 실행한다는 점을 보여준다.

## 5. 그림 3. 13주 현금 진단과 정책 후보

### 삽입 위치

공식 원고의 `2. 주요 기능 목록` 표 다음 또는 `3. 사용자 이용 흐름`의 `1단계. 진단` 설명 다음에 넣는다.

### 캡처 순서

1. 그림 2와 같은 가상 입력으로 진단을 실행한다.
2. 상권환경의 하방, 기준, 회복 범위가 표시된 상태에서 기준 범위를 선택한다.
3. `세 가지 상권 범위의 13주 현금 비교` 그래프와 `앞으로 28일 필요현금`이 보이게 한다.
4. 화면 아래의 정책 후보까지 내려가 최대 3개를 선택할 수 있다는 안내와 후보 카드가 보이게 한다.
5. 그래프 화면과 정책 후보 화면을 각각 캡처해 위아래 또는 좌우 2단으로 배치한다.

### 반드시 보일 요소

- 내 점포 최근 흐름과 상권·업종 전망의 구분
- 하방, 기준, 회복 범위
- 13주 현금 그래프와 현금 부족 구간
- 앞으로 28일 필요현금
- `자격이 확정된 목록이 아닙니다` 안내
- 정책 후보와 최대 3개 선택 안내

### 권장 자르기

첫 캡처는 진단 제목, 범위 선택, 필요현금과 그래프를 남긴다. 두 번째 캡처는 정책 후보 제목, 한계 안내와 카드 2~3개만 남긴다. 긴 정책 설명이나 화면 하단의 빈 공간은 제외한다.

### 캡션

> 그림 3. 상권환경 범위를 적용한 13주 현금 진단과 비교할 정책 후보 선택(가상 입력)

### 이 그림이 증명하는 내용

상권·업종의 집계환경과 사용자의 재무 입력을 구분해 현금위험을 계산하고, 자격 확정 전에 비교할 정책을 사용자가 직접 선택한다는 점을 보여준다.

## 6. 그림 4. 무대응 대비 선택 정책 비교

### 삽입 위치

공식 원고의 `3. 사용자 이용 흐름`에서 `2단계. 비교` 설명 다음에 넣는다.

### 캡처 순서

1. 그림 3에서 비교할 정책을 2개 또는 3개 선택한다.
2. `정책 비교로 이동`을 누른다.
3. `무대응과 선택 정책의 13주 현금 비교` 그래프가 완전히 표시될 때까지 기다린다.
4. 무대응 실선과 조건부 정책 점선, 그래프 범례가 함께 보이도록 한다.
5. 그래프 아래의 정책별 무대응 대비 차이 또는 선택 정책의 핵심 지표를 포함한다.
6. 비교 정책 중 하나는 가능하면 비차입 지원, 다른 하나는 신규 융자 성격으로 선택한다. 실제 화면에 표시된 후보와 계산 가능 여부를 우선한다.

### 반드시 보일 요소

- 현재 적용 중인 상권환경 범위
- 무대응 기준선과 선택 정책의 조건부 그래프
- 조건부 효과가 승인 가능성을 뜻하지 않는다는 안내
- 13주 뒤 현금 차이
- 신규 부채 또는 6개월 뒤 남은 부채
- 월 최대 상환액 또는 총이자

### 권장 자르기

비교 화면 제목부터 그래프와 정책별 핵심 지표까지 한 장에 담는다. 접힌 What-if 입력 영역, 화면 하단의 처음부터 다시 보기 버튼과 긴 설명은 제외한다.

### 캡션

> 그림 4. 무대응과 선택 정책의 현금경로, 부채와 상환 부담 비교(가상 입력·조건부 계산)

### 이 그림이 증명하는 내용

현금 유입만 강조하지 않고 신규 부채, 상환액과 총이자를 함께 보여주며, 확인되지 않은 정책 효과를 조건부로 분리한다는 점을 보여준다.

## 7. 그림 5. 정책별 자격조건과 공고 핵심정보

### 삽입 위치

공식 원고의 `3. 사용자 이용 흐름`에서 `3단계. 준비` 설명 다음에 넣는다.

### 캡처 순서

1. 그림 4에서 정책 한 건을 선택하고 `이 정책 확인 준비로 이동`을 누른다.
2. 정책명이 보이는 상태에서 자격조건 선택 영역을 연다.
3. `예`, `아니오`, `모름` 또는 정책별 값 선택지가 보이게 한다.
4. 조건 하나를 선택한 뒤 같은 화면에서 상태와 계산 가능 여부가 다시 표시되는지 확인한다.
5. 저장 공고 분석이 끝나면 신청 기간, 금융 조건, 신청 경로, 필요 서류, 문의처와 게시일 중 현재 펼쳐진 항목과 근거 상태를 포함한다.
6. 자격조건 화면과 공고 핵심정보 화면을 각각 캡처해 좌우 2단으로 배치한다.

### 반드시 보일 요소

- 현재 확인 중인 정책명
- 사용자가 답할 자격조건과 기관 확인 항목의 구분
- 조건 선택 뒤의 현재 상태 또는 조건부 효과 안내
- 공고 핵심정보 제목
- 신청 기간과 공식 공고 근거
- `현재 접수 여부 확인` 또는 공식 공고 이동 행동
- 신청 완료가 아니라는 안내

### 권장 자르기

첫 캡처는 정책명, 조건 선택과 상태 안내를 중심으로 자른다. 두 번째 캡처는 공고 핵심정보와 공식 링크를 중심으로 자른다. 긴 정책 상담 영역은 기본 그림에서 제외한다.

### 캡션

> 그림 5. 선택 정책의 자격조건 재확인과 근거가 검증된 공고 핵심정보 확인(가상 입력)

### 이 그림이 증명하는 내용

서비스가 정책을 자동 승인하거나 신청하지 않고, 사용자가 조건과 공식 공고를 확인한 뒤 신청기관의 공식 경로로 이동하도록 설계됐다는 점을 보여준다.

## 8. 그림 6. AI·데이터 처리 파이프라인

### 삽입 위치

공식 원고의 `4. AI 및 데이터 처리 방식`에 있는 처리 구조표 다음에 넣는다.

### 그림 형식

서비스 화면을 캡처하지 않고 HWPX의 둥근 사각형과 화살표로 직접 만든다. 가로형 3단 구조를 권장한다.

```text
[입력]
서울 상권·업종 집계 데이터
사용자 재무 입력
공식 정책 공고
사용자 What-if·정책 질문
        ↓
[처리]
상권환경 모델: 하방·기준·회복 범위
금융 엔진: 13주 현금·6개월 부채 계산
규칙 엔진: 정책 자격조건 확인
생성형 AI: 동의 문장 해석·공고 구조화·근거 설명
        ↓
[출력]
현금위험 진단
무대응 대비 정책별 현금·부채 비교
자격 상태와 추가 확인 조건
공고 핵심정보와 공식 신청 경로
```

처리 영역 아래에는 다음 경계 문장을 별도 상자로 넣는다.

> 생성형 AI는 자격, 정책 금액, 현금흐름, 부채, 정책 효과와 확정 비교 순위를 결정하거나 변경하지 않는다.

### 색상 구분

- 입력: 연한 회색
- 상권환경 모델과 생성형 AI: 연한 파란색
- 규칙 엔진과 금융 계산 엔진: 연한 녹색
- 사용자 출력: 연한 베이지색
- 권한 경계 문장: 흰색 바탕과 진한 테두리

색만으로 의미를 구분하지 않는다. 각 상자에 `AI`, `모델`, `규칙`, `금융 계산`을 텍스트로 적는다.

### 캡션

> 그림 6. 상권·재무·정책 데이터에서 현금·부채 비교와 공식 신청정보로 이어지는 처리 구조 및 AI 권한 경계

### 이 그림이 증명하는 내용

AI가 문장을 해석하고 공고를 설명하는 역할과 자격·금액·금융결과를 계산하는 역할을 분리했다는 점을 보여준다.

## 9. 선택 그림. AI What-if 또는 정책 상담

본문 공간이 충분할 때만 그림 4 또는 그림 5 아래에 보조 그림으로 추가한다. 필수 그림 6개보다 우선하지 않는다.

### AI What-if를 넣는 경우

1. 비교 화면에서 `AI What-if로 조건을 바꿔 보기`를 연다.
2. `매출이 10% 더 떨어지면?`처럼 화면에 제시된 예시를 사용한다.
3. 외부 AI 전송 동의 문구와 입력 가정, 적용 전후 결과가 함께 보이도록 한다.

캡션:

> 보조 그림. 사용자가 동의한 가정 문장을 제한된 범위로 해석하고 금융 엔진이 다시 계산한 What-if 결과(가상 입력)

### 정책 상담을 넣는 경우

1. 준비 화면에서 정책 상담을 연다.
2. `이 정책을 신청하기 전에 확인할 자격조건은 무엇인가요?`처럼 제공된 예시 질문을 사용한다.
3. 답변과 공식 공고 근거 링크가 함께 보이도록 한다.
4. 숫자와 식별정보 패턴 제거, 최대 5회와 페이지 이탈 시 삭제 안내를 포함한다.

캡션:

> 보조 그림. 선택 정책의 공식 공고 범위에서 근거와 함께 제공되는 정책 상담 화면

## 11. HWPX 삽입 후 확인

- 그림 1의 입력값과 결과 숫자가 제출 시점의 공개 서비스와 같은지 확인한다.

- 화면에 실제 개인정보, 브라우저 계정, 로컬 경로 또는 개발자 도구가 보이지 않는지 확인한다.
- 서비스 화면의 내부 버전명이 노출된 부분은 캡처 범위에서 제외한다.
- 조건부 정책을 확정·승인된 정책처럼 설명하지 않았는지 확인한다.
- 공고 핵심정보 확인 완료를 신청 완료처럼 표현하지 않았는지 확인한다.
- 캡션에 `가상 사례`, `가상 입력` 또는 `조건부 계산` 표시가 있는지 확인한다.
- 그림 6에서 생성형 AI와 규칙·금융 엔진의 권한이 분리돼 보이는지 확인한다.
- 이미지 안의 제목, 숫자, 그래프 범례와 공식 확인 문구가 PDF에서 읽히는지 확인한다.
- 이미지가 페이지 밖으로 잘리거나 다음 항목 제목을 밀어내지 않는지 확인한다.
- PDF 변환 뒤 흐릿함, 비율 왜곡, 색상만으로 전달되는 의미와 캡션 누락을 다시 확인한다.
