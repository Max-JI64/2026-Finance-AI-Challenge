## Stage Gate

### V5-0. 독립 기준선

- `v4/` 승인 소스 16개를 `v5/`로 복사했다.
- 캐시, 로그, `__pycache__`, V4 결과 기록은 복사하지 않았다.
- 복사 직후 16/16 해시가 일치했으며 `V4_COPY_BASELINE_SHA256.md`에 기록했다.
- V5 자산명, API 접두사, 버전, 세션키, 포트와 공고 캐시 경로를 분리했다.

### V5-1. 문서와 화면 셸

- 상단 진행은 `진단`, `비교`, `준비` 3개다.
- 해결 목적 5개는 단일 선택이다.
- 정상 경로의 발표 프리셋은 숨기고 `?demo=1`에서만 표시한다.
- 프리셋은 입력만 채우며 목적 선택이나 계산을 자동 실행하지 않는다.
- 계산에 연결되지 않던 운영 기간 입력을 제거했다.

### V5 Final. 종료 수정

- 첫 화면의 핵심 문구를 `추가 대출이 위기를 해결하는지, 부채만 늘리는지 계산합니다.`로 고정했다.
- 사용자가 선택할 때만 여는 `대표 사례 30초 보기`를 추가했다. 고정 가상 입력만 코드에 두고 무대응, 비차입 지원, 신규 정책자금의 결과 숫자는 기존 결정론 엔진에서 계산한다.
- 대표 사례는 첫 현금 부족 주차, 13주 현금, 6개월 뒤 남은 부채, 월 최대 상환액과 만기까지 총이자를 비교한다.
- `가상 사례`, `내 사업장 결과가 아닙니다`, 조건부 계산 한계와 개인 진단 이동을 함께 표시한다.
- `무엇부터 확인할지 모르겠음`을 기본값으로 적용하되 진단 뒤 제안 기준은 사용자가 확인하기 전 확정하지 않는다.
- 최근 월매출 붙여넣기, 최근 달 금액의 3개월 복사, `임대료 없음`, `직원 없음`, `대출 없음`, 남은 필수 입력 수, 첫 오류 항목 이동과 시기 가정 안내를 추가했다.
- 거래내역·대출 CSV는 기본 경로를 막지 않는 선택형 정밀 입력으로 유지했다.
- 첫 화면에서 저장 공고 기준일, 현재 접수와 최종 자격의 공식기관 확인, 승인·실행을 가정한 조건부 효과를 고지한다.

### V5-2. 검토 렌즈와 계획

- 현금 생존, 부채 부담, 비용 절감, 정책 유형 비교와 `unsure`를 엄격한 Schema로 제한했다.
- `unsure`는 진단 신호에 따른 기준을 제안하되 사용자 확인 전 검토 순서를 생성하지 않는다.
- 계획에는 목적, 사용자가 이해할 수 있는 재무 상태와 먼저 볼 효과만 포함한다.
- 감지 신호와 정책 지원방식은 내부 키 대신 금액과 의미가 포함된 한국어로 표시한다.
- 내부 설계 설명인 `질문 기준`과 `이번 선택이 실제로 바꾼 순서` 카드는 제거했다.
- 렌즈를 바꾼 두 실제 API 응답에서 후보, 자격, 시나리오, 정책 효과, 기존 순위 권한 해시가 모두 일치했다.

### V5-3. 정책별 자격조건 선택

- 진단과 비교 사이의 질문 게이트를 제거해 정책 후보를 바로 보여준다.
- 선택한 정책의 준비 화면에서 그 정책에 연결된 전체 검수 조건을 직접 선택지로 표시한다.
- 조건 선택은 같은 준비 화면을 유지한 채 자격 상태와 조건부 정책 효과를 다시 계산한다.
- 사용자가 답할 수 없는 접수 상태와 잔여 예산 등은 `기관에서 확인할 항목`으로 분리한다.
- 기존 질문 계획기와 질문 Trace는 실행 경로에서 제거했다.

### V5-4. 정책 비교

- 기존 `rank_position`과 V5 `review_position`을 분리했다.
- 사용자가 선택한 최대 3개 안에서만 금융 메커니즘별 검토 순서를 만든다.
- 검토 1번 정책, 이유와 렌즈별 지표 순서를 표시한다.
- 새 추천 점수나 금융 결과를 만들지 않는다.

### V5-5. 다음 공고 확인

- V4의 여섯 공고 필드와 필드별 근거 Fail-close를 유지했다.
- V5 캐시는 `v5/runtime/notice_extraction_cache.sqlite`만 사용한다.
- 신청 기간을 첫 항목으로 한 개만 펼치고, 나머지는 접힌 상세로 둔다.
- 분석 요청 중에는 회전 표시와 `AI가 공고를 확인하는 중` 문구를 노출한다.
- 완료 화면에서는 공고 조각 수와 원문 해시를 숨기고, 확인 수가 정책 개수가 아니라 선택 정책 한 건의 신청정보 여섯 항목임을 명시한다.
- 모든 항목을 읽으면 이 화면의 확인만 끝났다고 알리고 현재 접수 여부 확인과 정책 비교 복귀 행동을 제공한다.
- 확인 상태는 공고 원문 해시와 함께 브라우저 세션에 저장한다.

### V5-6. 하네스와 평가

- 입력, 검토 계획, 검토 순서, 공고 우선순위와 도구 Trace에 엄격한 Pydantic Schema를 적용했다.
- 금융 권한 해시와 도구 버전, 입출력 Schema 버전, 상태, 표시 이유를 응답에 남긴다.
- 고정 평가는 검토 렌즈 25개와 사용자 흐름 8개를 유지하고, 정책별 준비 조건이 공용 `POLICY_FIELDS` 계약과 정확히 일치하는지 회귀 테스트한다.
- 기존 질문 계획 30개 파일은 이전 설계 이력으로 보존하지만 현재 실행 경로의 성공 기준에는 포함하지 않는다.
